## Findings NOT fixed yet (tracked for Phase 1–4)

### 1. Sitemap coverage — `http:sitemap`

The scanner reports `/admin`, `/institutes`, `/coaching-institutes`,
`/coaching-institutes/bulk-create`, `/coaching-institutes/:id` as
"in code but missing from sitemap".

Verified: `/admin` is intentionally excluded (blocked by `robots.txt`).
`/institutes` and `/coaching-institutes*` do not appear as `<Route>`
declarations in `src/App.tsx` — the scanner is picking them up from admin
navigation or unused files. Action for Phase 1:

- Confirm via `rg` that no live route serves them.
- If confirmed unused, delete the dead references so the scanner stops
  flagging them.
- If a public `/institutes` alias is desired, add it to
  `supabase/functions/_shared/staticRoutes.ts` so SSR and sitemap stay in
  sync.

### 2. Lighthouse contrast — `lighthouse:lighthouse_accessibility`

Stale finding against published build. Action for Phase 1:

- Grep hand-written `text-gray-300`, `text-gray-400`, `text-muted-foreground/50`
  on light backgrounds and replace with `text-muted-foreground` or
  `text-foreground` tokens per the a11y guidance.

### 3. Lighthouse LCP — `lighthouse:lighthouse_performance`

Stale finding against published build. `index.html` preloads brand fonts
but no LCP image. Homepage hero is currently rendered inside a lazy
route, so the LCP candidate varies (news bar, hero title, or hero image).
Action for Phase 1:

- Identify LCP candidate on `/`, `/colleges`, `/college/:slug` with
  Chrome DevTools Performance panel.
- If image: set explicit `width`/`height`, drop `loading="lazy"`, add
  `fetchpriority="high"`, and preload from `index.html`.
- If text: ensure `font-display: swap` in every `@font-face` (already set
  for DM Sans; verify Plus Jakarta and any custom face).

## Structural / architectural observations

These are not scanner findings, but showed up during codebase review and
belong to later phases of the plan.

- **JSON-LD dedupe** (`src/hooks/useResolvedSeo.ts`) covers `FAQPage`,
  `BreadcrumbList`, `WebPage`, `Organization`. Should also treat
  `ItemList`, `CollectionPage`, `Course`, `EducationalOrganization` as
  singletons — currently over-emitted on colleges/coaching leaf pages.
- **Canonical host enforcement** (`src/lib/canonical.ts`) is centralised
  and correct. Manual `useEffect` canonical writes in
  `src/pages/CollegeProgrammeRedirect.tsx` bypass `SEOHead` and should be
  audited for other consumers so preview / www / lovable.app hosts never
  leak into canonical tags.
- **Sitemap `<lastmod>`** — `serve-sitemap` and the static
  `public/sitemap.xml` snapshot need to be inspected against the sitemap-
  lastmod policy: if any `<lastmod>` is derived from build/generation
  time (not a real per-page change), it must be dropped.
- **Legacy soft-404s** — `LegacyCollegeSlugRedirect` handles `-admission`
  / `-mba-admission` suffixes. GSC Soft-404 export should be diffed
  against covered patterns to ensure no cluster is left un-redirected.
- **AEO surface** — leaf templates (`ArticlePage`, `ExamDetailPage`,
  `CollegeHubPage`) do not yet render a short factual answer block
  (definition + entity list + key stats) above the fold. This is the
  single highest-leverage GEO change and is planned for Phase 3.
